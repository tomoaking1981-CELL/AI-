# 探究教室の住人 — AIキャラクター Webデモ(プロトタイプ)

「中学校の探究学習空間に常駐するAIキャラクターの共同開発と継続的関係形成に関する研究構想」を、
中学生とのワークショップ等で **触って体験できる形** にした、フロントエンドのみのデモです。

**これは実装済みのAIキャラクターそのものではありません。** 研究構想が定義している
「関係形成の型」(出会い→前回の確認→活動報告→変化の可視化→資源接続→次の一歩→次回への記憶)
を、ルールベースの簡易な台本で再現した、共同設計ワークショップ用の叩き台です。

## できること

- 簡易3D/Live2D風アニメーション(呼吸・まばたき・発話時の口パク)をするSVGキャラクター
- ブラウザ標準の音声合成(Web Speech API)によるキャラクターの発話
- 対応ブラウザでは音声入力(マイクボタン)にも対応
- 「QRを見せる(記憶で再会)」「記憶を使わず話す」「記憶を確認する」「記憶を削除する」
  「対話を終了する」という、研究構想 5.1〜5.4 章に対応した操作
- 「前回との差を事実として断定せず、本人に確認する」応答パターン(研究構想 5.3 の例文を採用)
- 会話の変化を横並びのタイムラインとして可視化する「変化ログ」

## かわいい3Dアバターに差し替える(VRM対応)

デフォルトの見た目(手描きSVG)は仮のものです。**同じフォルダに `avatar.vrm` という名前で
VRMファイルを置くだけで、自動的にかわいい3Dアバターに切り替わります**(three.js +
`@pixiv/three-vrm` を使用。どちらも無料のオープンソースライブラリで、CDN経由で読み込みます)。

### 無料で使えるVRMアバターの入手先(例)

著作権の関係で、私からVRMファイルそのものを直接お渡しすることはできません。以下のような
「商用利用可・改変可」を明記した配布元から、ご自身でダウンロードしてください。

- **VRoid Hub の公式サンプルモデル A / B / C**
  (VRoid Project 提供。利用条件の範囲内で自由に利用可。CC0のものも一部あり)
  → https://hub.vroid.com で「サンプルモデル」を検索、または各モデルページのライセンス欄で
    「商用利用可能」「改変可」を確認してからダウンロード
- **つくよみちゃん公式3Dアバター**(連絡不要・商用利用可のフリーキャラクター)
- **VRoid Hub 上の一般ユーザー投稿モデル**のうち、ライセンス欄が
  「アバターとして誰でも使える」「改変可」になっているもの
  (モデルごとに規約が異なるため、ダウンロード前に必ずライセンスを確認してください)

ダウンロードしたVRMファイルを `avatar.vrm` という名前にリネームし、`index.html` と
同じ階層に置いて `git add avatar.vrm` すればOKです。ファイルサイズは10〜20MB程度が一般的です。

### 注意点

- 学校での実運用を想定する場合、アバターのライセンス(改変可否・商用利用可否・
  「人格を与えることの許諾範囲」など)を必ず確認し、必要であれば著作者の連絡先に
  利用目的(中学校での探究学習用途である旨)を伝えることをおすすめします
- 研究構想10章にある「実在する生徒に似せたキャラクターにしない」という配慮点は、
  アバター選定の際にも当てはまります
- avatar.vrmを置かない場合は、これまで通りSVGキャラクターで動作します(フォールバック)

## できないこと(意図的な範囲外)

- 実際のLLMによる自由対話・RAGは組み込んでいません(台本ベースの固定応答です)
- 記憶はページを開いている間だけメモリ上に保持され、リロードすると消えます
  (ブラウザの `localStorage` は本デモでは意図的に使っていません。実運用時は下記「次のステップ」を参照)
- カメラによる在室検知、QRコードの実際の読み取りは未実装です(ボタンで模擬しています)
- 外部クラウドへの通信は一切行いません(音声合成・音声認識ともブラウザ内蔵機能のみ使用)

## GitHubへのアップロード方法

このフォルダには `index.html` と `README.md` の2ファイルのみです。ビルド不要です。

```bash
# 1. 新しいリポジトリを作る(GitHub上、またはCLIで)
git init
git add index.html README.md
git commit -m "探究教室AIキャラクター デモ プロトタイプ"

# 2. GitHub上に作成したリポジトリに紐付けてpush
git remote add origin https://github.com/あなたのアカウント/リポジトリ名.git
git branch -M main
git push -u origin main
```

## GitHub Pagesで公開する方法

1. GitHub上のリポジトリ → **Settings** → **Pages**
2. 「Build and deployment」の Source を **Deploy from a branch** に設定
3. Branch を `main` / フォルダを `/(root)` に設定して保存
4. 数分後、`https://あなたのアカウント.github.io/リポジトリ名/` で公開されます

ローカルで確認したいだけなら、`index.html` をブラウザで直接開くだけで動作します
(ただし音声入力はブラウザによって `https` または `localhost` を要求する場合があります)。

## 次のステップ(実運用に近づけるために)

研究構想の本実装では、以下が必要になります。このデモはその手前の「体験・共同設計用」の
段階として位置付けてください。

| 研究構想の要素 | このデモでの扱い | 本実装で必要なこと |
|---|---|---|
| ローカルLLMによる自由対話 | 台本ベースの固定応答 | 学校内スタンドアロンPCでのローカルLLM稼働、または外部送信をしない推論基盤 |
| 教室内資源のRAG参照 | 固定リストからランダム提示 | 書籍・教材・地域資料のインデックス化と検索 |
| QR認証 | ボタンで模擬 | 実際のQRコード発行・読み取り、生徒ごとの記憶ストア |
| 限定的記憶の永続化 | メモリ上のみ(非永続) | 生徒本人が確認・訂正・削除できる記憶DBの設計(研究構想 5.2, 10章) |
| 在室検知 | 常時点灯の演出のみ | 個人識別をしない接近検知(研究構想 8章 第2段階) |

**重要**: 本実装で外部のAI APIを利用する場合、研究構想 4.1・10章にある
「外部クラウドへ学習データ・対話内容を送信しない」という倫理方針との整合を、
必ず学校・教育委員会・研究倫理審査のプロセスの中で検討してください。
クライアント側のJavaScriptにAPIキーを直接埋め込む実装は、キーの漏洩リスクがあるため
本番運用では避け、サーバー側でAPI呼び出しを仲介する構成を推奨します。

## ワークショップでの使い方の例

研究構想 8章「第1段階：中学生との共同設計」のたたき台として、このデモを見せながら
次のような問いを生徒に投げかけることを想定しています。

- このキャラクターの見た目・話し方は、教室にいてほしい感じがする？
- 「前回の確認」の言い方は、しつこく感じる？ ちょうどよい？
- 記憶しておいてほしいこと・してほしくないことは何？
- 「変化ログ」に表示してほしい・してほしくない内容は？
